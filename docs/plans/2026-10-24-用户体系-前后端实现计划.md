# 用户体系（前后端）实现计划

状态：**已实施（2026-10-24，M0–M3 代码完成；M4 灰度待真实集群与 OAuth App 注册）** ｜ 依赖：无（可独立发布） ｜ 关联：[设计与架构](../specs/2026-10-24-用户身份与权限-设计与架构.md) · [接口草案](../../contracts/api/proposals/2026-10-24-auth.openapi.yaml)

本计划只覆盖「人」的身份与授权：GitHub 登录、会话、角色、权限中间件、console 的登录态与账户/审计面板。worker 的凭据、归属、认领见 [worker 认证与权限实现计划](2026-10-24-worker认证与权限-前后端实现计划.md)。

## 0. 交付面

| 面 | 交付物 | 仓 |
|---|---|---|
| 后端 | `auth.sqlite`、Provider、会话、角色、`require()` 中间件、9 个 `/auth/*` 端点、`ManagerData.owners` | `rvbench-official-manager` |
| 前端 | console 顶栏账户区、登录/退出、401 横幅、权限驱动的提交页、账户面板、审计面板（admin） | `rvbench-core-rust/webui/console.html` |
| CLI | `rvbench auth login / status / logout` + 凭据文件 | `rvbench-cli` |
| 契约 | 5 个 schema 进正本 | `rvbench`（主仓） |

**不做**：worker 记录与 claim（Plan 2）、suite 相关权限（P2）、refresh token（v1.1）、多租户。

## 1. 前置条件

| 项 | 谁 | 说明 |
|---|---|---|

## 2. 阶段

每个阶段结束都应可发布、可回滚。估算是单人有熟悉度前提下的上限，不含评审等待。

| `src/auth/error.rs` | `unauthenticated` / `forbidden` / `auth_disabled` 三个 code |
| `src/auth/routes.rs` | 最小版：仅 `GET /auth/config`（M0 验收要用；其余端点 M1 扩充） |
| `examples/job.json` | 从 `rvbench-core-rust/examples/job.json` 复制一份，供本地验收 curl 使用 |


### M1 登录闭环（约 2 天）

**目标**：能用 GitHub 登录，拿到 `rvb_` token，console 显示身份。

后端：

| 文件 | 改动 |
|---|---|
| `src/auth/provider.rs` | `IdentityProvider` trait：`authorize_url` / `exchange_code` / `exchange_token` / `userinfo` / `team_membership` |
| `src/auth/github.rs` | 四个 HTTP 调用；`read:user read:org`；`/user/teams?per_page=100` 分页 |
| `src/auth/static.rs` | 测试 provider，`access_token` 即 login |
| `src/auth/session.rs` | `rvb_` 生成（32B base64url）、sha256 存储、建立/查询/撤销/滑动续期 |
| `src/auth/routes.rs` | `/auth/login`、`/auth/callback`、`/auth/github/exchange`、`/auth/me`、`/auth/logout`、`/auth/config`；登录类端点按 IP 令牌桶限流（10/min，设计 §6）；cookie 态写请求（logout 等）做 Origin/Referer 校验（设计 D10） |
| `src/lib.rs` | 路由挂载；`/auth/*` 不挂在 `require` 下 |

前端（`console.html`）：

| 函数/位置 | 改动 |
|---|---|
| `api()` | 加 `credentials:'same-origin'`；401 时抛带 `status` 的 `AuthError`，由全局处理器展示横幅 |
| 新增 `loadAuth()` | 并行 `GET /auth/config` + `GET /auth/me`（401 视为未登录，不报错） |
| 新增 `renderAccount()` | 按四种状态渲染：未启用 / 未登录 / 已登录 / 降级 |
| 新增 `login()` / `logout()` | 登录用 `location.href`；退出先 `POST /auth/logout` 再重载 |
| `refresh()` | 首屏调用 `loadAuth()`，与 `refresh()` 并行，不阻塞状态渲染 |

验收：

```sh
# static provider 本地（provider 由 dev.json 配置项 kind=static 指定，见设计 D12；不用环境变量）
cargo run -p rvbench-manager -- --config dev.json
rvbench --base http://127.0.0.1:18800 auth login --static alice
rvbench --base http://127.0.0.1:18800 auth status   # 显示 alice / roles / token 前 8 位
curl -s -b cookiejar localhost:18800/auth/me | jq .principal.login   # 浏览器侧
```

手工检查 cookie：`HttpOnly`、`Secure`（https 时）、`SameSite=Lax`、`Path=/`。

## 3. 前端设计

### 3.1 信息架构

console 仍是 4 个 tab，认证相关不新增 tab，走顶栏弹层——tab 从 4 加到 6 在 1280px 以下会换行。

| 入口 | 位置 | 可见性 | 内容 |
|---|---|---|---|
| 账户 | 顶栏右侧，头像按钮 | `auth.enabled` | 身份、角色、权限、会话、退出 |
| 审计 | 账户弹层的第二个 tab | 仅 `admin` | 审计查询 |
| 登录 | 顶栏右侧，主按钮 | `enabled && !loggedIn` | 跳 `/auth/login` |
| 401 横幅 | 顶栏下方，通栏 | 会话失效时 | 「登录已失效」+ 重新登录 |

### 3.2 顶栏线框

```
┌──────────────────────────────────────────────────────────────────────┐
│ [rv] rvbench  评测控制台        [● 集群 Manager]  20:31  ◐  [C4Y ▾]   │
│ ──────────────────────────────────────────────────────────────────── │
│ [◉ 系统状态] [＋ 任务提交] [▤ 任务结果] [▥ 排行榜]                     │
└──────────────────────────────────────────────────────────────────────┘
                                                              │
                                        ┌─────────────────────┴──────┐
                                        │ C4Y  c4y                   │
                                        │ [user] [early_access]      │
                                        │ ─────────────────────────  │
                                        │ 账户                       │
                                        │ 审计（admin）              │
                                        │ ─────────────────────────  │
                                        │ 退出登录                   │
                                        └────────────────────────────┘
```

四种状态：

| 状态 | 判定 | 顶栏右侧 |
|---|---|---|
| 未启用 | `authConfig.enabled === false` | 不渲染（与今天完全一致） |
| 未知 | 首屏请求未返回 | 灰点 + 「…」，不可点 |
| 未登录 | `/auth/me` 401 | `登录` 按钮（accent 实心） |
| 已登录 | `/auth/me` 200 | 头像（login 首字母）+ login + 角色徽章；`roles_stale` 时加琥珀点 |
| 降级 | `roles_stale === true` | 同上，徽章后加 `!`，tooltip「角色校验失败，暂按普通用户」 |

### 3.3 登录与回跳

```
点击登录
  → location.href = '/auth/login?redirect=' + encodeURIComponent(location.pathname + location.hash)
  → GitHub 授权
  → GET /auth/callback?code&state  → 302 回 redirect（带 Set-Cookie）
  → 页面加载 → loadAuth() 拿到 me → 重渲染顶栏
```

- `redirect` 只带 `pathname + hash`，不带 origin；`#submit` 这类 tab 位置能保留。
- 401 横幅**不自动跳转**：用户可能正在看结果，跳走会丢上下文。横幅上给按钮。
- 退出：`POST /auth/logout` 成功后 `location.reload()`，避免残留内存态。

### 3.4 权限驱动

```js
const can = (p) => (me?.permissions || []).includes(p);
```

| 位置 | 无权限时 |
|---|---|
| 提交 tab 的表单 | 置灰 + 顶部提示条说明缺哪个权限；保留 tab 可见，避免用户以为功能消失 |
| 结果页「取消」按钮 | 隐藏（不是置灰：他人 job 连存在性都不该暴露） |
| 审计入口 | 不渲染 |
| 账户里的会话撤销 | 只显示自己的，admin 多一列「主体」 |

### 3.5 视觉规格

沿用现有变量，不新增色板。

| 元素 | 规格 |
|---|---|
| 角色徽章 | `user`：`--muted` 底/字；`early_access`：`--green-soft`/`--green`；`admin`：`--amber-soft`/`--amber`；`worker`（Plan 2 用）：`--accent-soft`/`--accent` |
| 徽章尺寸 | 高 20px，圆角 999px，字号 11px，padding 0 8px，字重 600 |
| 头像 | 28×28，圆角 8px，`--accent-soft` 底 + `--accent` 字，字号 12px |
| 下拉 | 宽 280px，`--panel` 底，`--shadow`，圆角 12px，`padding 6px` |
| 横幅 | 通栏，`--red-soft` 底，`--red` 左边框 3px，高 44px |
| 会话行 | 两行：UA 截断 + 「创建 10-24 · 最近 2 分钟前 · 过期 11-23」 |

暗色主题自动跟随 `[data-theme=dark]`，不需要额外规则。

### 3.6 空态与错误态

| 场景 | 文案 | 动作 |
|---|---|---|
| 未登录看提交页 | 登录后可提交算子任务 | 登录 |
| 无 `job:submit` | 当前账号没有提交权限，需要加入 EarlyAccessDevelopers | 查看权限说明（链到账户面板） |
| 登录已失效 | 登录已失效，请重新登录 | 重新登录 |
| GitHub 不可用（登录时） | 登录服务暂时不可用，请稍后重试 | 重试 |
| 角色校验失败 | 角色信息暂时无法刷新，已按普通用户权限运行 | 无（`roles_stale`） |
| 审计为空 | 暂无记录 | 无 |

## 6. 发布与回滚

| 步 | 内容 | 风险 |
|---|---|---|
| 1 | 协议仓加 5 个 schema → 打 rev | 低；只是 schema |
| 2 | manager 镜像（M0–M3）以 `mode=off` 上线 | 低；行为不变 |
| 3 | console 随协议仓 rev 一起发 | **中**：前端改动会触发协议仓 rev，三仓都要跟 rev 重编译 |
| 4 | `warn` → 观察 3 天 → `enforce` | 中；有回滚开关 |

前端改动的 rev 成本是这条路线最不顺手的地方。缓解：**把 M0–M3 的前端改动攒到一次 rev 升级**，不要每个小改动发一次。若后续前端迭代变频繁，再评估把 `console.html` 拆到独立包（会破坏 worker 复用同一控制台，需要单独评审）。

回滚：`auth.mode=off` + 重启 manager。cookie 与 `auth.sqlite` 留着不影响。

## 8. 风险

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| 1 | `api()` 是所有请求的咽喉，401 分支写错会连累公开页 | 全站白屏 | 401 只在带凭据的请求上触发；`/healthz` `/observability/*` 不抛；回归 4 个 tab |
| 2 | 前端改动触发协议仓 rev | 三仓跟 rev 重编译 | 攒批次；一次 rev 覆盖 M0–M3 |
| 3 | `warn` 模式指标噪声 | 误判为异常 | 只统计会 deny 的请求，按 permission 分组 |
| 4 | GitHub 组织限制 third-party App | 所有人登录失败 | 上线前用真实账号走一次完整授权 |
